# API reference

Every HTTP endpoint of the Mailbox Viewer backend: what it does, its inputs,
what it returns, its errors, and which frontend page uses it.

Source: `backend/api/main.py` (routes) and `backend/api/schemas.py`
(response shapes). The interactive version of this page is generated by
FastAPI at **http://127.0.0.1:8000/docs**.

---

## General

| Item | Value |
|---|---|
| Base URL | `http://127.0.0.1:8000` (set `API_URL` in the frontend to change it) |
| Start the backend | `cd backend` then `uvicorn main:app` |
| Authentication | None. The backend has no login (Task 1), so it must stay bound to `127.0.0.1`. |
| Format | JSON, except two endpoints: `/attachments/{id}` (the file) and `/schema/ddl` (plain text) |
| Times | Every timestamp is **IST** (`+05:30`), ISO 8601, e.g. `2026-10-14T13:17:00+05:30`. The database stores UTC; the API converts. |
| Docs | `/docs` (Swagger UI, try any call), `/redoc`, `/openapi.json` |

### Errors

Errors come back as `{"detail": "<what went wrong>"}` with these codes:

| Code | Meaning | Example |
|---|---|---|
| `404` | The thing asked for does not exist | `GET /threads/999` → `{"detail": "no thread 999"}` |
| `409` | Conflict: the action doesn't apply right now | a re-classify while a sync runs; closing a ticket that is already closed |
| `422` | A parameter is invalid | `GET /tickets?status=nope`, `limit=0` |

### Background jobs

Long work (sync, re-classify, re-decide, rebuild tickets) runs as a
**background job**. The `POST` answers at once with **`202 Accepted`** and a
job; you then poll `GET /jobs/{id}` until `state` is no longer `running`.

- **Only one job at a time.** Asking for the same kind of job while it runs
  returns the running job; asking for a different kind returns **409**.
- The backend keeps the last 20 jobs in memory; they are lost on restart.

**Job** (the shape every job endpoint returns):

| Field | Type | Meaning |
|---|---|---|
| `id` | string | Job id, e.g. `67d61130557f` |
| `kind` | string | `sync`, `reclassify`, `redecide` or `tickets` |
| `state` | string | `running`, `succeeded` or `failed` |
| `started_at`, `finished_at` | datetime (IST) | `finished_at` is null while running |
| `result` | object or null | Depends on `kind`; see each job endpoint |
| `error` | string or null | Why it failed |

## Service

### GET /health

Is the backend running, can it reach the database, which models are loaded.
Never fails: a database problem is reported in the body, not as an error.

**Response** `HealthOut`

| Field | Type | Meaning |
|---|---|---|
| `status` | string | `ok`, or `degraded` when the database is unreachable |
| `database` | string | `ok` or `error` |
| `database_error` | string or null | The database error, shortened |
| `model` | string | The loaded models, e.g. `body: laya, attachments: layoutlmv3-invoice` (`none` when a model folder is missing) |

```json
{"status": "ok", "database": "ok", "database_error": null,
 "model": "body: laya, attachments: layoutlmv3-invoice"}
```

### GET /profiles

The active business-purpose profile: what is synced and with which rules.
Returns a list with one profile.

**Response** list of `ProfileOut`

| Field | Type | Meaning |
|---|---|---|
| `name` | string | Profile name (`statement_recon`) |
| `active` | bool | Always `true` |
| `mailbox` | string | The mailbox address |
| `folders` | list of string | Synced folders, e.g. `["INBOX", "[Gmail]/Sent Mail"]` |
| `keep_policy` | string | `payment_only` or `every_message` |
| `model` | string | Loaded models |
| `model_min_confidence` | float | Review floor (0.5) |
| `body_min_confidence` | float | Laya's payment bar (0.7) |
| `attachment_decides_confidence` | float | Above this, the attachment decides alone (0.8) |
| `ticket_close_confidence` | float | Laya's bar for auto-closing a ticket (0.8) |
| `payment_labels` | list of string | `["invoice", "receipt", "statement"]` |
| `attachment_store` | string | Where attachment files are stored |

### GET /stats

The numbers behind the Overview. Kept to five database queries on purpose.

**Response** `StatsOut`

| Field | Type | Meaning |
|---|---|---|
| `threads` | int | Conversations stored |
| `emails` | int | Emails stored |
| `attachments` | int | Attachment files stored |
| `payment_threads` | int | Conversations with a payment document |
| `needs_review` | int | Emails decided `review` |
| `judged` | int | Emails judged, kept or not (rows in `decision_log`) |
| `dropped` | int | Judged but not stored (`judged − emails`) |
| `by_doc_type` | object | Stored emails per document type, e.g. `{"invoice": 3, "receipt": 1}` |
| `by_decision` | object | Judged emails per decision, e.g. `{"payment": 6, "review": 1, "none": 253}` |
| `sync_states` | list | One per folder: `folder_name`, `uid_validity`, `last_seen_uid` (the bookmark), `last_sync_at` |
| `tickets` | object | `open`, `in_progress`, `closed`, `oldest_active_days` (or null), `active_by_bucket` (`{"0–2 days": n, "3–7 days": n, "8+ days": n}`) |

## Jobs

### POST /sync

Fetch new mail from every folder in `IMAP_FOLDERS`, judge it, store
payment-related mail, update tickets, and move the bookmarks. Only mail after
each folder's bookmark is fetched.

**Request** no parameters. **Response** `202` with a Job.

**Result** when succeeded (`SyncResultOut`):

| Field | Meaning |
|---|---|
| `status` | `ok`, `partial` (connection lost mid-run) or `failed` |
| `candidates` | New emails found |
| `kept` | Stored |
| `payment_hits` | Stored as payment on their own content |
| `dropped` | Judged and not stored |
| `skipped` | Already judged earlier |
| `backfilled` | Earlier emails of a new payment thread fetched back in |
| `failed` | Emails that could not be fetched or stored |
| `tickets_opened`, `tickets_closed` | Ticket changes during this sync |
| `error` | Error text, or null |
| `duration_seconds` | How long it took |
| `summary` | One line, e.g. `0 kept (0 payment documents, 0 backfilled), 0 dropped, 0 already judged, 0 failed` |
| `folders` | Per folder: `folder`, `status`, `candidates`, `last_seen_uid`, `full_rewalk`, `error` |

### POST /reclassify

Re-run the models over **stored** mail (the mailbox is not contacted), oldest
first, writing only decisions that changed. Use after a model is retrained.

**Query parameters**

| Name | Type | Default | Meaning |
|---|---|---|---|
| `only_with_attachments` | bool | `false` | `true`: re-run only emails with attachments (LayoutLMv3 only; about 20 s) |

**Response** `202` with a Job. **Result**: `{"changed": <emails whose decision changed>, "model": "<loaded models>"}`.
**Errors**: `409` if another kind of job is running.

### POST /redecide

Re-apply the decision rules to the scores already stored. No models, no
mailbox; about a minute. Use after changing a threshold and restarting the
backend.

**Response** `202` with a Job. **Result**: `{"changed": n, "body_min_confidence": 0.7, "model_min_confidence": 0.5}`.
**Errors**: `409` if another kind of job is running.

### POST /tickets/rebuild

Delete and recreate every ticket from the stored payment conversations, as the
mail alone would have left them. Laya is asked the confirmation question for
replies in active tickets. **Manual closes and reopens are not kept.**

**Response** `202` with a Job. **Result**: `{"changed": n, "opened": n, "in_progress": n, "closed": n, "reopened": n}`.
**Errors**: `409` if another kind of job is running.

### GET /jobs/{job_id}

State and result of one job. The frontend polls this once a second while a
job runs.

**Path**: `job_id` (string). **Response** a Job. **Errors**: `404` if unknown
(for example after a backend restart).

### GET /sync/latest

The most recent sync job, or `null` if none ran since the backend started.

## Mail

### GET /threads

Conversations, most recent first.

**Query parameters**

| Name | Type | Default | Meaning |
|---|---|---|---|
| `payment_only` | bool | `false` | Only conversations with a payment document |
| `search` | string | — | Match the subject or a participant |
| `limit` | int | `1000` | 1 to 5000 |

**Response** list of `ThreadOut`

| Field | Type | Meaning |
|---|---|---|
| `id` | int | Thread id |
| `conversation_key` | string | Root Message-ID of the reply chain |
| `subject` | string | Subject |
| `message_count` | int | Emails in the conversation |
| `last_message_at` | datetime or null | Newest email (IST) |
| `has_payment` | bool | Has a payment document |
| `participants` | string | Senders, for display |
| `attachment_count` | int | Files in the conversation |

### GET /threads/{thread_id}

One conversation with every email, newest first, each with its people,
attachments and decision. Loaded in four database queries however long the
conversation is.

**Path**: `thread_id` (int). **Errors**: `404` if no such thread.

**Response** `ThreadDetailOut`: every `ThreadOut` field, plus `messages`, a list of:

| Field | Type | Meaning |
|---|---|---|
| `id`, `message_id` | int, string | Email id and its Message-ID |
| `subject`, `body_text` | string | Subject and plain-text body |
| `received_at` | datetime or null | When it arrived (IST) |
| `in_reply_to`, `references_header` | string or null | Threading headers |
| `has_attachments` | bool | |
| `matched_directly` | bool | Payment on its own content (false when inherited from the thread) |
| `doc_type`, `confidence`, `decision_reason` | | The email's label, score and reason |
| `participants` | list | `role` (from / to / cc / bcc), `name`, `address` |
| `attachments` | list | `id`, `filename`, `content_type`, `size_bytes`, `blob_key`, `doc_type`, `confidence`, `download_url` |
| `decision` | object or null | The decision log entry (see `/decisions`) |

### GET /attachments/{attachment_id}

The attachment file itself, with its real content type and file name
(`Content-Disposition: attachment`), so a browser downloads it.

**Path**: `attachment_id` (int). **Errors**: `404` if the attachment or its
file on disk is missing.

### GET /decisions/{message_id}

The decision for one email, **including emails that were judged but not
stored**: the audit trail behind every keep-or-drop.

**Path**: `message_id`, the email's Message-ID **with** its angle brackets,
URL-encoded (`<` → `%3C`, `>` → `%3E`).

**Response** `DecisionOut`

| Field | Type | Meaning |
|---|---|---|
| `message_id` | string | The email |
| `tier` | int | Which models decided: 0 none, 1 attachment, 2 body, 3 both |
| `decision` | string | `payment`, `review` or `none` |
| `confidence` | float or null | Score of the deciding model |
| `reason` | string or null | Why, in plain words, e.g. `body: receipt (0.75) -> payment: body model at or above 0.70` |
| `decided_at` | datetime | When (IST) |

**Errors**: `404` if the email was never judged.

## Tickets

### GET /tickets

Aging tickets: **active ones oldest first, then closed ones most recently
closed first**.

**Query parameters**: `status` (optional): `open`, `in_progress` or
`closed`. Anything else → `422`.

**Response** list of `TicketOut`

| Field | Type | Meaning |
|---|---|---|
| `id` | int | Ticket id |
| `thread_id` | int | Its conversation |
| `subject`, `message_count`, `last_message_at` | | From the conversation |
| `status` | string | `open`, `in_progress` or `closed` |
| `opened_at` | datetime | Received time of the first payment email |
| `in_progress_at` | datetime or null | When we first replied |
| `closed_at`, `closed_by` | datetime / string or null | When, and `auto` or `manual` |
| `close_reason`, `close_confidence` | string / float or null | Why it closed; Laya's score for an automatic close |
| `age_days` | float | Open tickets: until now; closed: until they closed |
| `bucket` | string | `0–2 days`, `3–7 days` or `8+ days` |

### GET /tickets/{ticket_id}

One ticket, plus `events`: its full history, oldest first.

**Event fields**: `event` (`opened`, `in_progress`, `closed`, `reopened`),
`actor` (`auto` or `manual`), `at` (IST), `message_id` (the email that
caused it, null for manual), `reason`, `confidence`.

**Errors**: `404` if no such ticket.

### POST /tickets/{ticket_id}/close

Close a ticket by hand, for example when payment was confirmed by phone.

**Body** (optional): `{"reason": "paid by bank transfer"}`. Without a reason,
"closed by hand" is recorded.

**Response** the updated ticket with its history (as `GET /tickets/{id}`).
**Errors**: `404` no such ticket; `409` already closed.

### POST /tickets/{ticket_id}/reopen

Reopen a closed ticket by hand.

**Body** (optional): `{"reason": "payment bounced"}`.

**Response** the updated ticket with its history.
**Errors**: `404` no such ticket; `409` not closed.

## Data model

### GET /schema

The tables as structured data, generated from the live code
(`mailbox_viewer/models.py`), so it always matches what is written.

**Query parameters**: `dialect` (optional): `sqlite` or `postgresql`; types are
shown for that database. Default: the one in use.

**Response** list of tables: `name`, `columns` (each: `name`, `type`,
`nullable`, `primary_key`, `unique`, `references`, `indexed`),
`constraints`, `indexes`.

### GET /schema/ddl

The `CREATE TABLE` and `CREATE INDEX` statements, as plain text.

**Query parameters**: `dialect`: `postgresql` (default) or `sqlite`.

### GET /tables

Every table with its live row count and column names:
`[{"name": "emails", "rows": 14, "columns": ["id", "thread_id", ...]}, ...]`.

### GET /tables/{name}/rows

Raw rows of one table, read-only. Only the eight application tables are
allowed, so no arbitrary SQL can be run through it.

**Query parameters**

| Name | Type | Default | Meaning |
|---|---|---|---|
| `limit` | int | `100` | 1 to 2000 |
| `order_by` | string | primary key | Any column of the table |
| `descending` | bool | `true` | Newest / largest first |

**Response**: `{"name": ..., "total": <rows in the table>, "columns": [...], "rows": [{...}, ...]}`; datetimes in IST.

**Errors**: `404` unknown table; `422` unknown `order_by` column.

## Try it

In the browser: **http://127.0.0.1:8000/docs**, then pick an endpoint →
**Try it out** → **Execute**.

From a terminal:

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/stats
curl "http://127.0.0.1:8000/threads?payment_only=true"
curl http://127.0.0.1:8000/threads/1
curl "http://127.0.0.1:8000/tickets?status=open"

# a job: start it, then poll with the id it returns
curl -X POST http://127.0.0.1:8000/sync
curl http://127.0.0.1:8000/jobs/<id>

# close a ticket by hand, with a reason
curl -X POST http://127.0.0.1:8000/tickets/1/close \
     -H "Content-Type: application/json" -d '{"reason": "paid by bank transfer"}'

# a decision, Message-ID URL-encoded
curl "http://127.0.0.1:8000/decisions/%3Cabc123%40mail.gmail.com%3E"
```

## What one click calls (frontend)

| You do | Calls |
|---|---|
| Open the app | `/health`, `/profiles` (sidebar) + the page's own calls |
| Open the Inbox | `/stats`, `/threads` |
| Click a conversation | `/threads/{id}`, `/tickets` (for the badge) |
| Click **Download** | `/attachments/{id}` |
| Open the Tickets page | `/stats`, `/profiles`, `/tickets`; selecting one adds `/tickets/{id}` |
| **✅ Close ticket** | `POST /tickets/{id}/close`, then the page reloads its data |
| **🔄 Refresh mail** | `POST /sync`, then `GET /jobs/{id}` about once a second until done, then the page reloads its data |

Read calls are cached in the frontend for 60 seconds; any change (Refresh,
maintenance jobs, Close, Reopen, **♻️ Reload data**) clears that cache.
